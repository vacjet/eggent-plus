# Память проекта по типам

`memory.md` в проекте — это то, что агент читает через месяц вместо истории чата. Если в нём
свалены факт, догадка и решение, то через месяц догадка читается как факт, а решение — как правило.
Поэтому у каждого типа свой раздел и своё обязательное поле, и это проверяет код.

## Разделы

```markdown
## Факты
- В индексе 112 страниц — источник: data/external/webmaster.json, 14.11.2026

## Допущения
- Просадка из-за сезона — проверить: сравнить с прошлым годом в Метрике

## Решения
- Чиним 404 первыми — 2026-11-14, причина: 23 страницы выпали из индекса

## Блокеры
- Нет доступа к staging — нужен VPN-профиль
```

Правила:

| Тип | Обязательно | Почему |
|---|---|---|
| Факт | `— источник: <файл, ссылка, дата>` | без источника это мнение, а не факт |
| Допущение | `— проверить: <чем подтвердить или опровергнуть>` | иначе оно живёт вечно |
| Решение | дата и `причина:` | без даты решение путается с фактом, без причины не пересматривается |
| Блокер | — | важно просто не потерять |

## Как писать

Только через скрипт — он не даст записать факт без источника:

```bash
python3 scripts/memory.py add memory.md --type fact --text "В индексе 112 страниц" --source "data/external/webmaster.json, 14.11.2026"
python3 scripts/memory.py add memory.md --type assumption --text "Просадка из-за сезона" --check "сравнить с прошлым годом в Метрике"
python3 scripts/memory.py add memory.md --type decision --text "Чиним 404 первыми" --reason "23 страницы выпали"
python3 scripts/memory.py add memory.md --type blocker --text "Нет доступа к staging"
python3 scripts/memory.py check memory.md
```

## Как читать

1. **Факты** — можно опирать выводы, если источник ещё существует (проверь файл).
2. **Допущения** — нельзя. Их либо проверяют тем, что записано в «проверить», либо переносят
   в факты вместе с источником.
3. **Решения** — это выбор на дату, а не закон. Их можно пересмотреть, но с новой датой и причиной;
   старую запись не стирать.
4. **Блокеры** — первое, что сообщать человеку, если работа встала.

## Чего не делать

- Не переносить допущение в факты «потому что похоже правдой». Только с источником.
- Не удалять старое решение: устаревшее решение с датой полезнее, чем пустое место.
- Не писать сюда журнал: ход работы — в отчётах и `docs/handoff.md`, память — только устойчивое.
- Не писать секреты, пароли и токены — только «где лежит».
