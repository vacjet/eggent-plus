# AGENTS.md — eggent-plus

## Что это

Сборка Eggent поверх upstream: русский интерфейс, почта, документы проекта в чате, предсказуемые
расходы. Код ядра берётся из `github.com/eggent-ai/eggent`, наши изменения — маленький набор
патчей. Это **не** отдельный продукт и не переписывание Eggent.

Полный контекст и причины решений — `docs/`: `roadmap.md`, `decisions.md`, `boundaries.md`,
`environment.md`, `handoff.md`, `sources/`.

## Структура

| Путь | Что |
|---|---|
| `patches/*.patch` | изменения ядра, применяются по порядку имён |
| `TOUCHED.md` | файлы ядра, которые патчим (источник конфликтов при обновлении) |
| `scripts/apply-patches.sh` | применение и проверка (`--check`) |
| `scripts/backup.sh`, `scripts/restore.sh` | копия и восстановление `data/` |
| `scripts/test-scripts.sh` | негативные тесты скриптов |
| `docs/` | план, решения, границы, окружение, исходные разборы |
| `tests/i18n/en-reference.json` | снимок английского словаря (ключи и подстановки) с тега |
| `.github/workflows/patches.yml` | CI: патчи на тег, локаль, словарь, сборка (включается после публикации) |
| `docker/Dockerfile` | образ с инструментами документов поверх `eggent-plus:base` |
| `mail-adapter/` | адаптер IMAP → контракт почтового сервиса Eggent (Python stdlib, без зависимостей) |
| `skills/external-sources/` | скилл и скрипты чтения внешних источников (сайт, Метрика, Вебмастер, Директ); ставится в данные экземпляра, ядро не патчит |
| `upstream/` | рабочая копия upstream (клон тега); **не коммитится** |

## Что в этот репозиторий не попадает

Репозиторий публичный, и им делятся с другими людьми. Здесь только работа над патчем:
код, патчи, проверки, обезличенные документы. **Личное — в приватной заметке воркспейса**
(`notes/eggent-plus-private.md` в репозитории `home`), не здесь:

| Нельзя | Как писать |
|---|---|
| домены, dev-поддомены, адреса сайтов | `<сайт>`, `example.ru` |
| названия кампаний, счётчики, суммы, визиты, конверсии | `<кампания>`, `<N>` |
| почтовые адреса, телефоны, реквизиты, юрлицо | `<ящик>`, `<фирма>` |
| IP, номера LXC/VM, имена хостов | `<ip>`, `<номер>` |
| пути и имена SSH-ключей, токены | `<ключ>`, `$TOKEN` |
| статистика прогонов с реальными числами | «N кампаний», «расход N ₽» |

Проверка — `python3 scripts/check-private.py` (входит в `./check.sh`): общие шаблоны (IP,
почта, ключи, токены, рубли) плюс личный денлист `../notes/eggent-plus-deny.txt`, который
лежит **вне** репозитория. Денлист в репозиторий не кладётся: иначе проверка сама станет
утечкой.

## Правила

1. **Патч — последнее средство.** Сначала конфиг, скилл, Pi-расширение или файл в `data/`.
   Темы, специалисты, шаблоны промптов, навыки — контент, они не патчат ядро.
2. **Один патч — одна логическая правка.** Русская локаль, `kb_search`, скриптовые расписания,
   IMAP, «принять/отклонить» — отдельные файлы, иначе откат одной вещи тянет остальные.
3. **Патч обязан ложиться на чистый тег** upstream: `./scripts/apply-patches.sh --check` на свежем клоне.
4. **Проверка обязана уметь падать.** Пункт без негативного теста не считается сделанным.
5. **Ничего не менять в `/app` живого экземпляра.** Там сборка без исходников; правки исчезают при
   обновлении образа. Всё, что должно жить, живёт в этом репозитории.
6. **Секреты** — ни в патчи, ни в `docs/`, ни в чат. Ключи лежат в `data/` экземпляра.
7. **Данные пользователя** (`data/`) не удалять и не перезаписывать без подтверждения; перед любым
   разрушительным шагом — `scripts/backup.sh`.
8. **Не расширять продукт** за границы из `docs/boundaries.md`: CRM, почтовый клиент, платформа
   интеграций, ERP, PM-система, биллинг — не наша работа.
9. Обновление Eggent не должно ломать сборку: новый тег сначала прогоняется через CI, потом релиз.

## Команды

```bash
./check.sh                              # обязательные файлы, секреты, тесты скриптов, локаль, CI
./scripts/apply-patches.sh --check      # наложение патчей на checkout upstream/ (или $EGGENT_UPSTREAM)
./scripts/apply-patches.sh              # применить
./scripts/test-scripts.sh               # тесты скриптов отдельно
python3 scripts/check-i18n.py           # ключи и подстановки ru против снимка en
python3 scripts/check-workflow.py       # CI-файл: YAML, шаги, тег upstream
python3 scripts/check-touched.py        # каждый файл патча перечислен в TOUCHED.md
cd upstream && npm run -s test:vocabulary   # словарь намерений (тест upstream)
docker build -f docker/Dockerfile -t eggent-plus:documents .   # на сборщике LXC <номер>
./docker/deploy-test.sh                    # собрать из патчей и заменить тестовый контейнер (сборщик)
```

## Definition of done

- `./check.sh` проходит; для правки кода — сборка и ручная проверка сценария.
- Патч накладывается на чистый тег upstream (`--check`).
- Добавлена строка в `TOUCHED.md`; при новой возможности — пункт в `docs/roadmap.md`.
- Решение, меняющее продукт, записано в `docs/decisions.md` с датой и причиной.
- Если что-то не проверено — так и сказать, а не выдавать за готовое.

## Опасные команды

- `~/.ssh/authorized_keys` и другие файлы доступа править **только отдельными шагами**: `cp` в копию →
  проверить код возврата → правка во временный файл → `install` поверх → `wc -l` до и после.
  Никогда не перенаправлять вывод в тот же файл в цепочке: если `cp` не сработал, `>` уже обнулил
  файл, и доступ теряется вместе с резервной копией. Инцидент 13.11.2026 — ровно это.
