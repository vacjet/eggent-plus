# eggent-plus

Неофициальная сборка [Eggent](https://github.com/eggent-ai/eggent) поверх upstream: русский интерфейс,
почта из коробки, документы проекта в чате, предсказуемые расходы.

Это **не форк в смысле «свой продукт»**: код ядра берётся из upstream, наши изменения — маленький
набор патчей поверх выпуска. Обновления Eggent не должны ломать сборку: каждый новый тег upstream
проверяется CI, и если патч не лёг — релиза нет.

Название и логотип Eggent принадлежат проекту; сборка не выдаётся за официальную.

Репозиторий: `github.com/<owner>/eggent-plus` (**публичный**), ветка `main`, CI — `.github/workflows/patches.yml`.

Публичность — причина правила: в репозитории нет данных заказчика. Домены, кампании, суммы,
адреса и IP пишутся плейсхолдерами (`<сайт>`, `<кампания>`, `<ip>`), реальные значения — в приватной
заметке воркспейса.

## Как это работает

```
upstream (eggent-ai/eggent, тег vX.Y.Z)
        │
        ├── main  — зеркало upstream, только fast-forward
        └── our   — main + patches/*.patch
                       │
                       └── образ ghcr.io/<owner>/eggent-plus:plus-X.Y.Z.N
```

Правило: **сначала конфиг, скилл, расширение или файл в `data/`; патч ядра — последнее средство.**
Темы, специалисты, шаблоны промптов и навыки — контент, они живут отдельно и не патчат ядро.

## Порядок работы над патчем

1. Клон upstream на нужном теге, ветка `our`.
2. Правка, проверка (`npm run check`, свои тесты), затем `git diff > patches/000N-<тема>.patch`.
3. `./scripts/apply-patches.sh --check` на чистом клоне тега — патч обязан лечь.
4. `./check.sh` — проверить, что скрипты и обязательные файлы на месте.
5. Релиз только после зелёного CI.

## Проверки

```bash
./check.sh                        # обязательные файлы, секреты, тесты скриптов, локаль
./scripts/test-scripts.sh         # скрипты применения патчей и копий, отдельно
python3 scripts/check-i18n.py     # ключи и подстановки ru против английского снимка
python3 scripts/check-i18n.py --self-test   # негативные тесты самого валидатора
cd upstream && npm run -s test:vocabulary   # словарь намерений (тест upstream, 10 проверок)
```

## Внешние источники (этап 4)

Скилл `skills/external-sources/` читает сайт (`robots.txt`, `sitemap`, коды страниц) и Яндекс
(Метрика, Вебмастер, Директ). Ядро не патешно: скилл копируется в данные экземпляра.

```bash
./scripts/install-skills.sh /root/eggent-plus/testdata-ru   # в skills проекта
python3 skills/external-sources/site_audit.py --site https://example.ru --out /tmp/ext
python3 skills/external-sources/yandex_read.py --source all --token-file /путь/к/secrets.env --out /tmp/ext
python3 skills/external-sources/site_audit.py --status --out /tmp/ext
cd skills/external-sources && python3 -m unittest discover -s tests   # без сети и токенов
```

Только чтение. Коды возврата: `0` — прочитано, `1` — источник недоступен, `3` — ошибка
авторизации. Подробности — `docs/stage-4-plan.md`.

## Данные

Данные экземпляра — в `data/` рядом с приложением (в образе `/app/data`). В репозиторий они не
попадают: `.gitignore`. Копия делается `scripts/backup.sh`, восстановление — `scripts/restore.sh`,
он отказывается писать в непустой каталог и проверяет контрольную сумму.
