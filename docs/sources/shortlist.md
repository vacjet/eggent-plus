### Отброшено окончательно

- Генеративный UI на React из ответа модели (HTML-страницы закрывают 80%).
- Отдельный режим «исследование» (субагенты + доска уже это).
- Изолированные среды разработки и sandbox-интерпретатор (есть терминал; N150 не потянет).
- Профили как отдельная система настройки — только как пакет-наследование (§1.12).
- Code Interpreter, Agent Marketplace, Admin Panel, OIDC/SSO, OpenTelemetry/Langfuse, resumable streams, speech, presets — у нас есть или не нужно на одного пользователя.
- Автосжатие и ручное сжатие контекста — **уже есть** (`chat-runner.ts`, `chat-panel.tsx`), в LibreChat это не новинка для нас.

## 2. Почта: что есть в коде и что делать

**Факт (проверено в 0.8.0):**

- Интерфейс письма уже написан: `src/components/mail/` — `mail-thread-view.tsx`, `mail-contacts-list.tsx`, `mail-reply.tsx`, `use-mail-contacts.ts`.
- API: `src/app/api/mail/{thread, read, send, assign, contacts, attachments/[id]}` и `src/app/api/email/{letters, status, assign}`.
- Логика: `src/lib/email/{client, config, sync, store, notice, owner-letters, tool-guard, smtp}.ts`, письма лежат в `data/email/`.
- `sync.ts` первым делом проверяет `getEmailConfig()?.mode !== "service"` и выходит: **входящие работают только в облачном режиме** (`EGGENT_EMAIL_API_URL` + services token).
- В self-host режим только `smtp`: отправка есть, **входящих нет** — README прямо: «There is no inbox on a server of your own».

**Вывод:** «почта в панели» — это не новая фича, а **второй провайдер к готовому интерфейсу**: IMAP вместо облачного сервиса. Работа распадается на три уровня:

| Уровень | Что видно | Как | Сложность |
|---|---|---|---|
| A | Отправленные агентом (`data/email/sent.jsonl`) в панели | только чтение своего журнала, без IMAP | малая |
| B | Входящие и отправленные из ящика | IMAP-провайдер в `src/lib/email/`, тот же `store`/`thread` | средняя |
| C | Ответ из панели, назначение письма проекту, уведомление агенту о новом письме | `mail/reply`, `mail/assign`, `notice.ts` | средняя |

**Ограничения, которые надо учесть:**

- Пароль приложения Яндекса — в env/data, не в git; доступ только чтение по умолчанию, отправка — после подтверждения человеком.
- Ловушки IMAP у нас уже описаны в скилле `yandex-imap-mail-analysis`: тела по Content-Type, пачки по 10, переподключение — переиспользовать, не изобретать.
- Письма в `data/email/` — не индексировать в `.kb/` и не коммитить; вложения хранить отдельно.
- Два ящика (рабочий и второй домен) — решить, подключаем один или оба.
