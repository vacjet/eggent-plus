# Этап 4 — чтение из внешних источников

Дата: 14.11.2026. Основание: `docs/roadmap.md`, этап 4. Границы — `docs/boundaries.md`
(«два-три конкретных источника через скилл/MCP», не платформа интеграций).

## Решение

**Скилл + скрипты, без патча ядра.** Ни одной строки upstream не меняется: скилл живёт в данных
экземпляра (`data/projects/<id>/skills/external-sources/`), запускается `python3` из образа,
данные пишет в `data/external/`. Расписание — из этапа 1 (`data/scripts/schedules.json`,
задание без модели, ноль токенов за прогон).

Почему не MCP-сервер: оба источника — это несколько GET/POST-запросов и запись файла; сервер
добавил бы ещё один процесс, конфиг и точку отказа, ничего не упростив. Если появится источник
с интерактивным входом — там MCP уместнее.

## Источники и что они дают

| Источник | Что читаем | Файл данных |
|---|---|---|
| Сайт | `robots.txt`, `sitemap` (с заходом в индекс), коды страниц, редиректы | `external/site/pages.json` |
| Метрика | счётчики и визиты/посетители по месяцам (12 мес) | `external/yandex/metrika.json` |
| Вебмастер | сайты, страницы в поиске и исключённые, ИКС, обход, sitemap по данным сервиса | `external/yandex/webmaster.json` |
| Директ | кампании (`Campaigns.get`) и отчёт по дням (`Reports`, только чтение) | `external/yandex/direct.json` |

Общий статус — `external/status.json`: когда обновлялось, что получилось, какие объекты доступны.
Читается командой `--status` у любого из двух скриптов.

## Шаги

| Шаг | Что | Проверка |
|---|---|---|
| 4.1 | Сайт: `site_audit.py` — robots, sitemap (включая индекс), до N страниц, находки (не 200, редиректы) | юнит-тесты на подставном HTTP; живой прогон `example.ru` |
| 4.2 | Яндекс: `yandex_read.py` — Метрика, Вебмастер, Директ; коды возврата 0/1/3 | юнит-тесты (включая 401/403 и повтор 202); живой прогон только чтением |
| 4.3 | Установка в экземпляр и расписание: `scripts/install-skills.sh`, задание без модели | скилл на стенде `:3100`, запуск виден в `data/scripts/runs.jsonl` |

## Приёмка этапа (из дорожной карты) и где она закрыта

| Требование | Чем закрыто |
|---|---|
| сломанный токен даёт «ошибка авторизации» | HTTP 401/403 → `AuthError`, код возврата 3, запись в `status.json`; тест `test_broken_token_gives_auth_exit_code_and_status_error` |
| статус показывает время обновления и доступные объекты | `status.json` + `--status`: `lastRun`, `ok/error`, `objects`; тест `test_status_has_time_error_and_objects` |
| повторный запуск не создаёт дублей | данные лежат словарями по ключу (URL, счётчик+месяц, хост, дата+кампания), повтор перезаписывает; тесты `test_rerun_*` |
| запуск по расписанию из этапа 1 | `data/scripts/schedules.json`, `runs.jsonl`; проверено на стенде |
| только чтение | Директ: `Campaigns.get` и `Reports`; записи в Метрику/Вебмастер/Директ нет ни в одном пути кода |

## Команды

```bash
# юнит-тесты (без сети и токенов)
cd skills/external-sources && python3 -m unittest discover -s tests

# сайт
python3 skills/external-sources/site_audit.py --site https://example.ru --limit 20 --out /tmp/ext

# Яндекс: токены из окружения или из файла 600
YANDEX_SEO_TOKEN=… YANDEX_DIRECT_TOKEN=… \
  python3 skills/external-sources/yandex_read.py --source all --out /tmp/ext

# статус
python3 skills/external-sources/site_audit.py --status --out /tmp/ext

# установка в экземпляр
./scripts/install-skills.sh /root/eggent-plus/testdata-ru
```

## Чего здесь нет

- **Записи в источники.** Ни изменения ставок, ни правки кампаний, ни отправки в индекс.
- **OAuth-мастера.** Токены выпускаются руками по `seo/audit/yandex-access.md`; скилл только
  читает готовый токен и честно говорит «ошибка авторизации».
- **Хранения истории.** Один срез на источник, перезаписывается. История за период — из самих
  сервисов (Метрика отдаёт месяцы, Директ — дни в запрошенном периоде).
- **Директа на запись и рассылок.** Это за границей этапа.
