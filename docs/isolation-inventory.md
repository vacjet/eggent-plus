# Инвентаризация секретов: что терминал агента видит сейчас

Проверено 13.11.2026 на стенде (`eggent-ru`, 0.8.0+plus.7).

| Что | Где | Права | Видит ли терминал агента |
|---|---|---|---|
| Контейнер целиком | `docker exec eggent-ru id` | — | **uid 1000 (node), как и само приложение** |
| Ключи провайдеров, каталог | `/app/data/pi-agent` | `700 node` | да: терминал работает тем же uid 1000 |
| Ключи провайдеров, файл | `/app/data/pi-agent/auth.json` | `600 node` | да, по той же причине |
| Модели и провайдеры | `/app/data/pi-agent/models-store.json` | `600 node` | да |
| Токен сервисов | env процесса | — | да: `docker exec … env` показывает `EGGENT_SERVICES_TOKEN` |
| Настройки приложения | `/app/data/pi-agent/settings.json` | `644 node` | да |
| Письма (копия адаптера) | `/app/data/email` | `700 node` | да |
| Чаты, проекты | `/app/data/chats`, `/app/data/projects` | `644/755` | да (это и нужно агенту) |

Вывод: **права файлов сами по себе ничего не дают**, пока терминал агента работает тем же
пользователем, что и приложение. `700 node` на `pi-agent` защищает от других пользователей, а
другого пользователя в контейнере нет.

## Что нужно сделать (шаг 1 этапа 3)

1. Отдельный пользователь для команд агента: `agent` (uid 1001, без домашнего каталога).
2. Приложение остаётся `node` (uid 1000) и владеет секретами: `pi-agent` уже `700 node`, файлы `600`.
3. Терминал агента запускается с `uid/gid` этого пользователя (`src/lib/terminal/run-shell.ts`:
   `spawn(..., { uid, gid })`), с общей группой, чтобы писать в проект.
4. Проекты и чаты, куда агенту нужно писать, переводим в группу `work` (`g+w`), секреты — нет.
5. Переменные окружения: секреты нужны приложению, значит остаются у процесса `node`; терминал
   агента получает **урезанный** env (без `EGGENT_SERVICES_TOKEN`, без ключей провайдеров).
   `/proc/<pid>/environ` чужого uid и так не читается.

## Проверка, которую обязана проходить правка

Терминал агента (из чата):

```bash
cat /app/data/pi-agent/auth.json   # должно быть Permission denied
env | grep -i token                 # пусто
```

И одновременно должны продолжать работать: запись файлов в проект, `tesseract`, `soffice`,
`git` в проекте, чтение `/app/data/chats` своего чата.

## Риски

- Часть инструментов Pi пишет в проект из процесса приложения (не из терминала) — их права не
  меняются; после правки проверить сценарий «создай файл в проекте и покажи».
- Если пользователь `agent` не сможет писать в проект, сломаются все сценарии с файлами — поэтому
  сначала группа `work` и `g+w`, потом смена uid.
