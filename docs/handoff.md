# Как начать работу в новом чате

## Порядок чтения (15 минут)

1. `AGENTS.md` — правила и что можно/нельзя.
2. `context.md` — где мы сейчас.
3. `docs/roadmap.md` — этапы и приёмка.
4. `docs/boundaries.md` — чего не делаем (границей отсекается половина предложений).
5. `docs/stage-0-plan.md` — ближайший шаг с командами.
6. `docs/decisions.md` — почему так; не переспрашивать решённое.
7. `docs/environment.md` — где сервер, как собирать.
8. `docs/sources/` — исходные разборы: предложения, требования, шортлист. Читать только при спорах.

## Раздел «Почта» из Cloud: почему не сейчас (13.11.2026)

В Cloud раздел есть, но не в теге `v0.8.0`, а в `main`: `src/app/dashboard/email/`, `src/components/email/*`
(8 компонентов), `src/app/api/email/*` (letters, status, assign). Контракт сервиса там тот же, что
реализует наш адаптер — сверено по `src/lib/email/client.ts` в `main`.

Отсюда два вывода:

1. Когда мы поднимем тег до релиза с этим разделом, «Почта» появится сама и заработает с адаптером
   без правок: словарь дополнится ключами, и `scripts/check-i18n.py` покажет ровно их.
2. Портить `v0.8.0` портом этого раздела не нужно: это страница, восемь компонентов, три маршрута,
   навигация и ключи — и всё это станет конфликтом при следующем теге.

Отдельно: у Cloud есть карточка согласования (`email-approval-card`) — письмо «не своему» ждёт
разрешения человека. Наш адаптер возвращает `approval: null` и `pending: []`, то есть шлёт сразу.
Это осознанная разница, и её надо либо оставить (проще), либо сделать своё подтверждение в чате.
Решение за владельцем.

## Этап 1 закрыт — что дальше

Остался последний открытый пункт этапа 1. Две части, обе без переделки макета:

1. **Расход по проекту.** Сумма по чатам проекта — то же, что уже считается по чату, только по списку
   чатов проекта на сервере. Показывать — блок в «Настройки → Модели» рядом с выбором модели

   когда сумма по чату переходит порог — подпись «за чат N» становится предупреждающей и появляется
   одна строка-предупреждение в ответе, без блокировки. Поле ввода — «Настройки → Дополнительно».
   Блокировку не делаем: это биллинг, а он за границей (`docs/boundaries.md`).

Порядок: сначала 1 (данные), потом 2 (настройка и предупреждение). Каждый шаг отдельным патчем.
