# Этап 2 — почта (план)

**Решение 13.11.2026: делаем адаптер (`mail-adapter/`), а не патч ядра.** См. `docs/decisions.md`,
решение 34. Пункты 2.2–2.4 ниже остаются как проверка того, что адаптер закрывает.

Цель: видеть в Eggent письма из своих ящиков и отправленные агентом — **не** почтовый клиент.
Границы уже записаны (`docs/boundaries.md`): списка писем, открытия письма, вложений и статуса
синхронизации достаточно; контакты, метки, папки как в клиенте, ответ из интерфейса и поиск по всему
ящику — не делаем.

В upstream 0.8.0 почта есть только в облачном режиме (`src/lib/email/*`): провайдер OAuth, синхронизация
через API. Для self-hosted нужен режим `imap` рядом с облачным — это и есть единственный патч этапа
(`src/lib/email/config.ts`, `src/lib/email/sync.ts`).

## Шаги

### 2.1. Конфигурация ящиков

Несколько ящиков в `data/`, секреты отдельно, права 600.

```json
// data/mail/accounts.json
{ "accounts": [
  { "id": "work", "address": "mail@example.com", "mode": "imap",
    "host": "imap.yandex.ru", "port": 993, "tls": true,
    "folder": "INBOX", "days": 30 }
] }
```

Пароли — не здесь: файл `data/mail/secrets/<id>` с правами 600 или переменная окружения.
Приёмка: два ящика читаются, переключение без перезагрузки, файл секретов не попадает в git и в логи.

### 2.2. Провайдер `imap` рядом с облачным

`mode: "imap"` в конфиге ящика; синхронизация тянет письма за N дней, тела и вложения сохраняет в
`data/mail/<account>/…`. Уже проверено на практике (скилл `yandex-imap-mail-analysis`): тела читать
по `Content-Type`, пачки по 10 с переподключением — иначе Яндекс рвёт соединение.

Приёмка: входящие за 30 дней; русское письмо с вложением открывается и вложение скачивается.

### 2.3. Статус синхронизации

Карточка отвечает на четыре вопроса: когда обновлялось, успешно ли, что доступно (ящики и папки),
и что режим только для чтения.

Приёмка: неверный пароль даёт понятную ошибку в карточке и в журнале, а не пустой список.

### 2.4. Отправка агентом (только чтение чужого ящика)

Ящик агента — отдельный SMTP; ответ на письмо человека не делаем. Приёмка: письмо уходит, ошибка
авторизации видна текстом.

## Проверки, которые должны появиться

- `scripts/test-mail-accounts.ts` — чтение конфигурации, права на файл секретов, отказ при 0644.
- `scripts/test-mail-imap.ts` — разбор письма по MIME без сети (фикстура с русской темой и вложением).
- Негативные: пароль в `accounts.json` (должен быть отказ), отсутствующий ящик, битый MIME.

## Риски

- Два экземпляра на одном ящике (живой Eggent на VM <номер> и тестовый на LXC <номер>) — только чтение, поэтому
  конфликтов нет, но статус синхронизации у каждого свой.
- Пароли приложений Яндекса могут требовать подтверждения — проверить на одном ящике до кода.
