# Журнал решений

Каждое решение — с датой и причиной. Новый чат не переспрашивает то, что здесь записано; если
решение меняется, старая строка остаётся с пометкой «отменено».

## 12.11.2026 — начало работ

| № | Решение | Причина |
|---|---|---|
| 1 | Сборка называется **eggent-plus**, неофициальная | не выдаём за проект Eggent; имя сменить дёшево, пока нет релизов |
| 2 | Стратегия: `main` = зеркало upstream, `our` = патчи, CI на каждый тег | обновления Eggent не должны ломать сборку; поломка видна в день релиза, откат — прошлый тег |
| 3 | Патчи только там, где нельзя обойтись конфигом/скиллом/расширением | чем короче список в `TOUCHED.md`, тем дешевле обновления |
| 4 | Репозиторий сначала локально, GitHub — с первым рабочим релизом | не публиковать сырое |
| 5 | Русская локаль — первый патч, ~1960 строк, пишется заново | в upstream только `en`, в текущей сборке русского нет вообще |
| 6 | Макет не трогаем | переделка UI = конфликты при каждом обновлении и редизайн вместо функций |
| 7 | Fork разговора не делаем | путает; историю и версии файлов достаточно |
| 8 | Возобновление хода с контрольной точки после рестарта не делаем | дорого, выгода мала; ход помечается прерванным |
| 9 | Почта: только чтение входящих и отправленные, несколько ящиков, IMAP | ответ из интерфейса — это уже почтовый клиент |
| 10 | Провайдера моделей не зашиваем (никакого neuraldeep по умолчанию) | вкусовщина; в базу идёт только универсальный async-адаптер картинок |
| 11 | whisper остаётся `whisper.cpp` в образе, `faster-whisper` не добавляем | голос нужен; проверить работу, а не менять движок |
| 12 | CRM, учётные системы, запись в них — не делаем | иначе это другой продукт; готовность = не закладывать свою модель клиента |
| 13 | Справочники — файлы в проекте (CSV/JSON + `.kb`), без отдельного хранилища | нет объёма и запросов; SQLite — когда понадобится |
| 14 | Расходы: счётчики + мягкий порог с предупреждением, без блокировки | блокировка превращает помощника в биллинг |
| 15 | Специалисты = пакеты контента (промпты + скиллы + MCP), не подсистема | ядро upstream сознательно не поставляет контент (0.2.0) |
| 16 | Автовыбор специалиста — видимый бейдж + переключение одним кликом | невидимая маршрутизация непонятна и стоит токенов |
| 17 | Шаблоны промптов живут внутри пакета специалиста | отдельная библиотека — второй набор инструкций |
| 18 | Темы — файлами в `data/`, не движок и не каталог | CSS-переменные уже есть; тема `tokyo-night.user.css` это подтверждает |
| 19 | Русификация — сквозная, в каждом этапе, а не отдельный проект | иначе английские строки вернутся с новыми функциями |
| 20 | Инструменты документов (tesseract+rus, gs, pandoc, soffice, poppler, matplotlib) — в образ | без них агент не работает с документами из коробки; +350–450 МБ |

## 13.11.2026 — первый патч (русская локаль)

| № | Решение | Причина |
|---|---|---|
| 21 | `src/i18n/messages.ts` всё-таки правится — ровно две строки: импорт словаря и `ru: ruMessages` | `messages` объявлен как `Record<SupportedLocale, MessageDictionary>`, и с `ru` в `SUPPORTED_LOCALES` без ключа не сходится `tsc`. Английские тексты не тронуты, `git diff` по файлу — две добавленные строки |
| 22 | Импорт словаря идёт через `@/i18n/messages.ru`, а не относительным `./messages.ru` | относительный путь без расширения Node не резолвит, а node-тесты upstream (`--experimental-strip-types`) грузят `messages.ts` напрямую: с `./messages.ru` падали `test:skill-refresh`, `test:mail`, `test:empty-answers` и другие с `ERR_MODULE_NOT_FOUND`. Алиас `@/` понимают и бандлер, и загрузчик тестов |
| 23 | Словарь намерений двуязычный: английские записи остаются, русские добавляются | агент читает английские письма, документы и скиллы; записи — альтернативы регулярок, лишняя не мешает. Исключение — стоп-фразы: они сравниваются с целым сообщением, ложное срабатывание дороже |
| 24 | Русские глаголы в `INTERRUPT_VERBS` — формы с отрицательным просмотром (`останови(?!л)`), а не основы | основы ищутся в любом месте строки: «останов» ловил «процесс остановился сам», и runtime решал, что просят убить процесс. Тест upstream проверяет именно это |
| 25 | `DEFAULT_LOCALE = "ru"` | сборка русская: там, где нет `Accept-Language`, серверные строки должны быть по-русски. Следствие, принято сознательно: папка вложений почты называется «Сообщения», а upstream-тесты `test:mail`/`test:email` ждут путь `Messages/...` и с русским дефолтом падают (проверено: `test:mail` — 20 проверок, 5 падений на пути `Messages/Boris/report.txt`); с `EGGENT_DEFAULT_LANGUAGE=en` — 20/20. Вернуться к вопросу, если серверные строки начнут мешать |

| 26 | Репозиторий опубликован 13.11.2026: **публичный** `github.com/<owner>/eggent-plus`, ветка `main`, запись по deploy key; CI включён | владелец попросил пуш раньше «первого релиза» (решение 4). Приватный — потому что публиковать сырую сборку рано; отменяет решение 4 в части «локально до релиза» |

| 27 | Async-картинки поддерживаются общим способом: если в ответе нет картинок, но есть id задачи, инструмент опрашивает адрес результата (из ответа либо `<baseUrl>/images/tasks/<id>/result`) с потолком по числу попыток и по времени | привязка к одному агрегатору сломалась бы на следующем; `id` и `result_url` — то, что такие API и так отдают. Проверка — `scripts/test-image-async.ts` (13 кейсов, без сети) |

| 28 | Скриптовые расписания — своё хранилище (`data/scripts/schedules.json`) и журнал (`data/scripts/runs.jsonl`), цикл стартует из `instrumentation.node.ts`; задания `pi-subagents` не используются | задание там — это `prompt`, то есть ход модели: «запусти check-all.sh» стоило бы токенов на пустом месте. Свой цикл не зависит от живой сессии и переживает рестарт; журнал — одна строка JSON на запуск, чтобы провал был виден через неделю |

| 29 | Расход по чату считается на клиенте из `piRuntimeStats` каждого ответа, а не хранится отдельно; подпись «за чат N» встаёт в существующую строку счётчиков хода | статистика уже лежит в каждом сообщении, второе хранилище разошлось бы с ней. Строка счётчиков уже есть — макет не меняется (решение 6). По проекту пока не считаем: нужен список чатов и решение, где это показывать |

| 30 | Репозиторий публичный, поэтому секреты не хранятся и не попадают в патчи: ключи живут только в `data/` экземпляра (вне репозитория), `check.sh` сканирует рабочее дерево, CI дополнительно сканирует всю историю git | публичный репозиторий делает утечку необратимой: удалённый файл остаётся в истории и в форках. Патчи собираются из чистого клона тега, куда `data/` не копируется |

| 31 | Расход по проекту читается из `data/chats/*.json` фильтром по `projectId` и показывается строкой в «Настройки → проект → Модель» | проект уже знает свои чаты, а каждый чат — свою статистику; нового хранилища не нужно. Место — существующая карточка модели проекта: макет не меняется |

| 32 | Номер сборки — `0.8.0+plus.5.98a76b6` (тег upstream, число патчей, коммит), а не счётчик сборок вроде `0.8.0.1321`; пишет его развёртывание в `data/build-info.json`, читает `GET /api/build-info`, показывает «Общие» настройки | по номеру патчей сразу видно, вошла ли нужная правка; счётчик сборок этого не говорит. Файл пишет deploy, а не сборка образа: один образ можно развернуть дважды, и человеку нужно знать, что работает сейчас |

| 33 | Мягкий порог расхода — настройка `general.usageSoftLimitTokens` (0 = выключено), предупреждение подсвечивает сумму чата и пишет порог в подсказке; блокировки нет | владелец просил «предсказуемые расходы», а не биллинг: остановка хода — это лимит с блокировкой, он за границей. Порог приходит вместе с чатом в `/api/chat/history`, чтобы не делать второй запрос на каждую синхронизацию |

| 34 | Почта на self-hosted — свой адаптер IMAP → контракт облачного сервиса (`mail-adapter/`), а не патч ядра и не зависимость в `package-lock.json` | в 0.8.0 почта — тонкий HTTP-клиент к сервису; IMAP в ядре нет. Адаптер даёт встроенному `eggent_email` работать без правок ядра, а экрана писем в Cloud тоже нет — терять нечего |

| 35 | Адаптер почты на стенде запускается отдельным процессом на сборщике и говорит с контейнером через `host.docker.internal:8787`; секреты — `mail-data/secrets/<id>` (600) и `mail-data/adapter.env` (600), не в репозитории | ядро не патчится, а данные ящика и токен не попадают ни в git, ни в образ. Автозапуск после перезагрузки — отдельная задача (сейчас `/root/mail-adapter-start.sh`) |

| 36 | Экран «Почта» из Cloud **не портируем** в v0.8.0: он появится с обновлением тега, а наш адаптер уже говорит на его контракте (`/status`, `/messages`, `/read`, `/attachments/:n`, `/send` — сверено с `main`) | порт — это страница, 8 компонентов, 3 маршрута, навигация и ключи словаря, и всё это конфликтует с апстримом при следующем теге. Пока агент читает почту через `eggent_email`, а человек получит раздел вместе с тегом |

| 37 | Письмо на чужой адрес не уходит сразу: адаптер создаёт заявку, отправляет шестизначный код на адрес владельца и **не сохраняет это письмо в своей копии**, а агент подтверждает кодом (`POST /approve`) | по правилу проекта необратимое действие — только после подтверждения; код идёт каналом, который агент не читает (сам ящик), поэтому подтвердить за человека он не может. Письмо на свои адреса уходит сразу |

| 38 | Адаптер и секрет ящика вынесены на отдельный LXC <номер> (`eggent-mail`, <ip>), доступ по SSH — только ключ владельца; в Eggent остаются URL и токен | проверено: с ключом агента SSH отказывает. Но **граница не закрыта полностью**: у агента остаётся root на Proxmox, а `pct exec 106` читает секрет. Настоящая изоляция требует отозвать и ключ Proxmox — это решение владельца, а не техники |

| 39 | Доступ агента к Proxmox отозван: ключ удалён, у владельца — свой; изоляция почтового LXC стала настоящей | `pct exec` был обходом границы (решение 38). Инфраструктурные работы теперь только по просьбе владельца, с временным возвратом ключа |

| 40 | Чтение внешних источников — скилл + скрипты (`skills/external-sources/`) в данных экземпляра, а не MCP-сервер и не патч ядра; данные — один срез в `data/external/`, ключ записи = URL / счётчик+месяц / хост / дата+кампания | оба источника — это несколько запросов и запись файла; MCP добавил бы процесс, конфиг и точку отказа, ничего не упростив. Ключ записи вместо журнала — чтобы повторный запуск по расписанию не плодил дубли: требование приёмки этапа 4. Скилл живёт в данных, значит обновление образа его не затирает, а ядро остаётся чистым для следующего тега |

| 41 | В публичном репозитории нет данных заказчика: домены, названия кампаний, суммы, визиты, адреса, IP, номера LXC и ключей — только плейсхолдеры (`<сайт>`, `<кампания>`, `<ip>`, `<ящик>`, `<N>`); реальные значения — в приватной заметке воркспейса | репозиторий публичный и им делятся с другими людьми: техническая история не должна раскрывать, с какими сайтами, кампаниями и расходами ведётся работа. Плейсхолдер не мешает проверке: команды и тесты читаются так же, а числа подставляются в приватной копии |

| 42 | Работа над патчем и личная работа разделены: публичный `eggent-plus` — только патч, проверки и обезличенные документы; окружение, доступы, статистика и данные заказчика — в приватной заметке воркспейса (`notes/eggent-plus-private.md`, репозиторий `home`); автоматическая проверка `scripts/check-private.py` с денлистом вне репозитория | «личное» не должно утекать случайно: достаточно один раз записать адрес или сумму, и это уже в публичной истории. Разделение держится не на памяти, а на проверке в `./check.sh`; денлист вне репозитория — потому что список настоящих значений сам является утечкой |
