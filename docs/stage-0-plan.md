# Этап 0 — подробный план

Цель этапа: получить воспроизводимую сборку «upstream + наши патчи» и первый патч — русскую локаль.
Этап считается сделанным, когда `./check.sh` зелёный, патч накладывается на чистый тег, и приложение
на порту 3100 открывается по-русски.

Каждый шаг: цель → команды → ожидаемый результат → приёмка. Если шаг не сработал — стоп, запись
в `docs/handoff.md`, дальше не идти.

---

## 0.1. Сборщик (сделано 13.11.2026)

LXC <номер> `build-eggent-plus` на Proxmox: Debian 13, 2 ядра, 4 ГБ RAM, 32 ГБ, IP `<ip сборщика>`.
Ключ доступа `<каталог ключей>/<ключ сборщика>`. Docker ставится тремя пакетами — в Debian 13
`docker.io` даёт только демон:

```bash
apt-get install -y docker.io docker-cli docker-buildx docker-compose
```

Приёмка: `docker run --rm hello-world` отрабатывает; `free -m` показывает 4 ГБ.

## 0.2. Клон upstream (сделано 13.11.2026)

```bash
ssh -i <каталог ключей>/<ключ сборщика> root@<ip сборщика>
mkdir -p /root/eggent-plus && cd /root/eggent-plus
git clone --depth 1 --branch v0.8.0 https://github.com/eggent-ai/eggent.git upstream
cd upstream && git switch -c our && git describe --tags && wc -l src/i18n/messages.ts
```

Ожидаемо: `v0.8.0`, `1864 src/i18n/messages.ts`. (В `main` этой же осенью уже 2059 — тег отстаёт;
перевод делаем по теге, а не по main.)

## 0.3. Базовый образ без наших правок

```bash
cd /root/eggent-plus/upstream && docker build -t eggent-plus:base .
```

Ожидаемо: код 0, образ `eggent-plus:base`. На 2 ядрах это долго — часы, не минуты.

Приёмка:

- **негативный тест**: после базовой сборки внести заведомо неверный импорт в любой файл `src/`,
  собрать — сборка обязана упасть; откатить правку (`git checkout -- .`);
- тестовый экземпляр: `docker run -d --name eggent-test -p 3100:3000 -v /root/eggent-plus/testdata:/app/data eggent-plus:base`
  → `curl -s localhost:3100/api/health` отвечает.

Живой Eggent на VM <номер> не трогаем: тестовый экземпляр живёт на сборщике.

## 0.4. Патч `0001-ru-locale` (сделано 13.11.2026)

Цель: русский интерфейс. Три файла:

1. `src/i18n/locales.ts` — добавить `"ru"` в `SUPPORTED_LOCALES`, пункт в `LOCALE_OPTIONS`, значение
   по умолчанию — по языку браузера, иначе `ru` для нашей сборки.
2. `src/i18n/messages.ru.ts` — новый файл перевода по `src/i18n/messages.ts` (1864 строки на теге).
   Делить на проходы: меню и навигация → настройки → ошибки и пустые состояния → чат → доска →
   файлы и версии → расписания → почта.
3. `src/i18n/vocabulary.ts` — русские намерения и стоп-слова.

Фактически в патче четыре файла: к трём выше добавилась регистрация словаря в `messages.ts` —
две строки (импорт и `ru: ruMessages`), иначе `Record<SupportedLocale, …>` не сходится с `tsc`.
Словарь — 1770 ключей.

Правила перевода (из нашего опыта, скилл `ru-i18n-verification-eggent`):

- английский `messages.ts` не трогать никогда;
- подстановки `{name}` сохранять один в один;
- числительные не склеивать с формой (`{keep} дней` ломается на 21) — использовать сокращения;
- падежи: русский не склоняет подставленное значение, поэтому `Действия: {name}`, а не
  `Действия для {name}`;
- отрицательные формулировки (стоп, «не убивай», расписание, память) проверять отдельным кейсом.

Приёмка (все четыре обязательны):

- число ключей ru = числу ключей en, лишних нет;
- расхождений в подстановках `{...}` — 0;
- `tsc --noEmit` по файлам i18n без ошибок;
- приложение на порту 3100 открывается по-русски: меню, настройки, ошибка входа.

Проверка запуска:

```bash
PORT=3100 npm start &     # или npm run dev
```

Каталог данных: приложение пишет в `./data` рядом с собой (в образе это `/app/data`). Для пробы
скопировать текущий `data/` в `upstream/data/` **без каталога `projects/`** — он большой и для
проверки интерфейса не нужен.

## 0.5. Упаковка и проверка патча (сделано 13.11.2026)

```bash
cd /app/data/projects/eggent-plus/upstream
git add -A && git diff --cached > ../patches/0001-ru-locale.patch && git reset
cd .. && ./scripts/apply-patches.sh --check     # на текущем checkout
git -C upstream stash list                       # рабочая копия должна быть чистой
```

Приёмка:

- `--check` возвращает 0 и печатает `ok (check)`;
- **негативный тест**: испортить в копии патча одну строку контекста → `--check` возвращает 1;
- отдельно проверить на свежем клоне: `git clone --depth 1 -b v0.8.0 <upstream> /tmp/fresh && cd /tmp/fresh && git apply --check ../patches/0001-ru-locale.patch`.

После успеха: строка в `TOUCHED.md` (уже есть), запись в `docs/handoff.md`.
