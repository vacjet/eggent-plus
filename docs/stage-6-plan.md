# Этап 6 — контроль результата

Дата: 14.11.2026. Основание: `docs/roadmap.md` (этап 6), границы — `docs/boundaries.md`.

## Задача этапа

Сейчас сборка отвечает, но не проверяет, что работа доведена: правку файла нельзя принять или
отклонить, карточка доски закрывается без указания, чем проверено, память проекта мешает факты,
допущения и решения в один список, а опасные команды не различаются по риску. Этап закрывает
именно это — и ничего сверх: не биллинг, не роли, не многошаговые согласования.

## Границы

1. **Макет не трогаем.** Всё встраивается в существующие экраны: панель файлов, карточка доски,
   настройки проекта.
2. **Патч — последнее средство.** Сначала формат + проверка + скилл; ядро правим только там, где
   без него не обойтись (правка файла, карточка доски).
3. **Проверка умеет падать.** У каждого пункта — негативный кейс.
4. **Ничего не удаляем и не переписываем молча.** Отклонение правки — это новая версия файла, а не
   потеря старой; история хранится как сейчас.

## Шаги

| Шаг | Что | Ядро | Состояние |
|---|---|---|---|
| 6.1 | Типизированная память: факт / допущение / решение / блокер, источник у каждого; проверка формата и «решение не растекается в факты» | нет | сделано 14.11.2026 (`scripts/memory.py`, `skills/typed-memory/`) |
| 6.2 | Контракт готовности в карточке доски: карточка без «чем проверено» не закрывается | да, но маленький: правило при переводе в `done` | сделано 14.11.2026, патч `0016-card-proof` |
| 6.3 | «Принять / отклонить» правку файла: дифф → принять или вернуть версию | нет: история версий уже есть, не хватало повода и решения | сделано 14.11.2026, патч `0017-file-review` |
| 6.4 | Ask / Allow / Deny для опасных команд (`rm -rf`, `pct destroy`, `git push --force`, чтение секретов) | да: обёртка Pi-тула `bash` | сделано 14.11.2026, патч `0018-command-policy` |

Порядок выбран по цене: 6.1 без патча и сразу полезен, 6.2 — одно правило в существующем переходе,
6.3 — работа с уже готовой историей версий, 6.4 — самое рискованное, делается последним.

## Шаг 6.1 — типизированная память

`memory.md` проекта читается агентом и человеком; до сих пор это был свободный текст, где факт,
догадка и решение неразличимы, а источник нигде. Формат вводит четыре раздела и одно правило:

```
## Факты
- В индексе 112 страниц — источник: data/external/2026-11-14-webmaster.json, 14.11.2026

## Допущения
- Падение заявок из-за сезона — проверить: сравнить с прошлым годом по Метрике

## Решения
- Правки по 404 делаем в первую очередь — 14.11.2026, причина: 23 страницы из индекса

## Блокеры
- Нет доступа к staging — нужен VPN-профиль
```

Правила, которые проверяются (`python3 scripts/memory.py check <memory.md>`):

1. в «Фактах» у пункта есть источник (`— источник: …`), иначе это не факт, а мнение;
2. в «Допущениях» указано, что именно его подтвердит или опровергнет (`— проверить: …`);
3. в «Решениях» есть дата (`ГГГГ-ММ-ДД`);
4. пункт, дословно повторяющий допущение, не может лежать в «Фактах» без источника;
5. пустые разделы допустимы — «фактов нет» это тоже состояние.

Запись — тем же скриптом: `python3 scripts/memory.py add <memory.md> --type fact --text "…" --source "…"`.
Скрипт не придумывает источник: без него пункт не добавляется (код 1) — так правило держится не на
памяти агента, а на коде.

## Приёмка этапа

| Требование | Чем закрыто |
|---|---|
| «Решение» не растекается в общие правила | раздел «Решения» отделён, проверка требует дату и причину; скилл велит читать его как решение, а не как факт |
| Карточка без проверки не закрывается | шаг 6.2 |
| Правку можно принять или отклонить | шаг 6.3 |
| Опасная команда спрашивает / разрешается / отказывает | шаг 6.4 |

## Чего здесь нет

- Многошаговых согласований и ролей: один хозяин воркспейса, как и был.
- Отдельного хранилища памяти: `memory.md` остаётся файлом проекта (решение 1 от 12.11.2026).
- Автоматического превращения допущения в факт: это делает человек или модель, но с источником.

## Шаг 6.1: чем проверено

| Что | Как | Результат |
|---|---|---|
| Скрипт памяти умеет падать | `python3 scripts/memory.py --self-test` — 11 кейсов | 11/11 |
| Факт без источника | `## Факты` с пунктом без `— источник:` | «факт без источника — это мнение» |
| Допущение без способа проверить | пункт без `— проверить:` | ошибка |
| Решение без даты | пункт без даты | ошибка |
| Допущение выдано за факт | один текст в двух разделах | «допущение выдано за факт» |
| Память без разделов | свободный текст | «нет разделов» |
| `add` не даёт записать факт без источника | вызов без `--source` | код 1, файл не изменён |
| Память шаблона проверяется | убрал источник из `templates/seo/project/memory.md` | `check-templates.py` красный, вернул — зелено |

Скилл `skills/typed-memory/SKILL.md` объясняет агенту, что писать в какой раздел, как читать
(допущения не опирают выводы, решения пересматриваются с новой датой) и чего не делать
(не переносить допущение в факты, не стирать старые решения, не писать секреты).

## Шаг 6.2: карточка закрывается только с «чем проверено»

Правило живёт в одном месте — `moveCard(...)` в `src/lib/board/cards.ts`: перевод в `done` без
текста «чем проверено» отклоняется (`board.error.proofRequired`), с текстом — карточка получает
`proof: { text, at }`. Новый запуск (`queued`) стирает старый `proof`: закрытие вчерашней версии
не отвечает за сегодняшнюю.

| Что | Где |
|---|---|
| поле `proof` на карточке | `src/lib/board/types.ts`, чтение — `src/lib/board/store.ts` |
| правило | `src/lib/board/cards.ts` (`moveCard`) |
| API | `PATCH /api/board/cards/:id` → `{ move: { to: "done", proof: "…" } }` |
| экран | `src/components/board/card-sheet.tsx`: «Принять как готовое» открывает поле, пустое — кнопка неактивна |

Проверено на стенде: закрытие через API без `proof` — `400`, с текстом — `200`, в файле карточки
`proof` с датой; новый перевод в очередь очищает `proof`.

## Шаг 6.3: «принять / отклонить» правку файла — что уже есть в 0.8.0

Проверено по коду до начала работы (чтобы не строить второе рядом с готовым):

| Уже есть | Где |
|---|---|
| история версий файла, сравнение любых двух, восстановление любой | `src/lib/files/versions/` (`view.ts`, `service.ts`), `POST /api/files/versions/restore`, `components/files/version-history.tsx`, `version-diff.tsx` |
| восстановление пишется новой версией («restored from N»), старые не теряются | `restore/route.ts` → `captureAfter(... kind: "restore")` |
| отказ, если восстановление потеряет несохранённое (`code: "unkept"`, `force`) | там же |

Не хватает не механизма, а **повода и решения**: после хода, который изменил файл, человек не
видит «это правка агента, прими или отклони», и решение нигде не записывается. Значит шаг 6.3 —
это не «переписать историю», а:

1. после хода, изменившего файл, — строка «правка файла X: посмотреть дифф» рядом с карточкой файла
   (данные для неё уже собираются: `files-produced.ts`, `capture.ts`);
2. «Отклонить» — восстановление предыдущей версии через существующий маршрут и запись решения
   в чат/карточку файла; «Принять» — запись решения без изменения файла;
3. решение видно в истории: версия, из которой отклонено, остаётся в списке.

Что это НЕ делает: не блокирует работу агента, не требует подтверждения на каждую запись, не
меняет правила истории файлов (решение 4: ничего не удаляем молча).

## Шаг 6.4: Ask / Allow / Deny для команд оболочки

Проверка стоит **до запуска** процесса, в том же месте, где Eggent уже подменяет встроенный `bash`
своим интерактивным (`interactive-bash-tool.ts`). Три исхода:

| Исход | Что значит | Примеры |
|---|---|---|
| `deny` | «да» не сделало бы это безопасным | `rm -rf /`, `rm -rf ~`, `rm -rf /app/data`, `dd of=/dev/…`, `mkfs`, `git push --force`, `pct/qm destroy`, чтение `auth.json`/`.env`/ключей |
| `ask` | можно, но человек должен увидеть | `rm -rf build`, `rm -f файл`, `sudo`, `git reset --hard`, `docker rm/stop/prune`, `systemctl stop`, `curl … | bash` |
| `allow` | обычная работа | `ls`, `git status`, `npm run build`, `python3 scripts/check.sh`, `grep -rn`, `rm файл` без рекурсии |

Вопрос задаётся той же карточкой, которую ход уже транслирует в чат (`createPendingInteraction`,
`kind: "confirm"`): «Выполнить эту команду?» с причиной и самой командой. Где спросить некого —
ход из мессенджера, внешний API — команда **не выполняется** (иначе ход встал бы на вопросе, на
который некому ответить). Отказ возвращает код 126 и текст причины модели, чтобы она не повторяла
вслепую.

Исключения — `data/policies/command-policy.json` вида `{"allow": ["rm -rf build"]}`: сравнение по
целой строке после сжатия пробелов, не по префиксу (иначе исключение `rm -rf build` разрешило бы
`rm -rf build && rm -rf /`).

**Честная граница:** это защита от ошибки и от чужой инструкции в письме или на странице, а не
песочница. Агент работает тем же пользователем, и файл исключений ему доступен так же, как любой
другой.
